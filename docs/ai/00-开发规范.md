# AI 协作开发规范（所有分支必读）

> 本文件面向并行开发本项目的各个 AI。**开工前先读本文件，再只读你那一份任务书。**

---

## 一、项目一句话

WorldKnowledge · 世界知识门户：按「**阶段 × 学科**」导航人类知识，知识传统作为节点标签平级并列。三层架构：

| 层 | 技术 | 目录 |
|---|---|---|
| 门户 | Next.js（官方模板，App Router + Tailwind） | `apps/web` |
| 后台/数据 | Directus（headless CMS） | `apps/admin` |
| 后端 | FastAPI + SQLModel（薄层，只读） | `apps/api` |

## 二、先读这些（事实来源）

1. `世界知识门户项目知识文档.md`（仓库根）——**唯一事实来源**，定位/知识体系/选型全在里面
2. `packages/types/index.ts` —— 前后端共享类型（含 `Stage`/`Discipline`/`Tradition`/`KnowledgeNode`/`ApiEnvelope`）
3. `apps/api/app/data/skeleton/*.json` —— 骨架契约（4 阶段 / 12 学科 / 5 知识传统），**只读**

## 三、铁律：不重复造轮子

能用成熟开源就用，禁止自造轮子。CRUD / 用户 / 权限 / REST → **Directus**；登录鉴权不自研；内容不自己从零编，复用开放知识库（Wikidata / Wikipedia / OpenAlex）。**只自研**：四阶段×12 学科×传统模型、节点/边 schema、门户导航、MDX 内容。

## 四、分支纪律（最重要）

- **只在你的 worktree 里工作，只提交到你的分支。** 不要 `merge main`、不要 rebase 别人的分支——合并由主控在 `main` 收口。
- **只改你任务书「独占文件」里列的东西**，其余一律不碰。
- **冻结契约文件，任何分支都不许改**：
  - `packages/types/index.ts`
  - `apps/api/app/data/skeleton/*.json`
  - `docker-compose.yml`（只归 `02` 分支）
  - `世界知识门户项目知识文档.md`
- 若你确实需要改冻结文件：**不要动手**，写进总结「请求主控协调」。

## 五、提交规范

- 小步提交，一个逻辑一提交。
- 格式：`type(scope): 中文描述`
  - `type` ∈ `feat` | `fix` | `chore` | `docs` | `refactor` | `test`
  - 例：`feat(admin): 新增 nodes 集合与公开读权限`
- 不提交：密钥、`.env`、`node_modules`、构建产物。
- 结尾可选加：`Co-Authored-By: kuoleroy <kuoleroy@outlook.com>`

## 六、代码风格

- **Python**：4 空格缩进；全量类型注解；docstring 用中文；沿用 `apps/api/app/` 现有分层（`api/v1`、`schemas`、`models`、`core`、`db`）。
- **TypeScript / TSX**：沿用 `apps/web` 现有风格；服务端组件优先；样式用 Tailwind；路径别名 `@/*`、`@wk/types`。
- 注释只在逻辑不直观处写，且用中文。
- 新依赖必须属于文档已选型的技术栈；确需新增时，选成熟 + MIT/Apache-2.0，并在总结写明理由。

## 七、环境、依赖与自证

### 7.1 依赖由人类/主控统一提供（不要自己起）

- **不要自己 `docker compose up`** 起 mysql / directus / api / meilisearch——依赖由人类统一提供，**所有分支共用一套**
- **不要抢端口**：`:3000`(web dev) / `:8000`(api) / `:8055`(directus) 同一时刻只能一个进程用；本地自测请用**备用端口**：`next dev --port 3100`、`uvicorn --port 8001`
- 依赖**已预装**可直接用（`node_modules`、`apps/importer/.venv`）；只有**新增依赖**时才需要自己跑一次 `install`
- **严禁手工编辑 `pnpm-lock.yaml`**；合并时锁文件如冲突，由主控在 `main` 重新安装解决

### 7.2 必须自证（不许空口）

完成前必须**实际跑过**并记录结果：

| 层 | 验证 |
|---|---|
| web | `pnpm --filter web build` 通过；关键页面渲染出预期内容 |
| api | `uvicorn app.main:app --reload` 能起；相关端点返回预期 JSON |
| compose | `docker compose config` 通过；必要时实际 `up -d` 拉起验证 |

总结里给出「**跑过的命令 + 实际结果**」。没验证的事，不许写成"应该可以"。
