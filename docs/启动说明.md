# 世界知识门户 · 一键起全栈（Docker Compose）

一条命令在干净环境起全栈：`mysql + directus + meilisearch + api + web`，门户以容器化方式运行。

> 本说明对应分支 `kuoleroy/docker-compose-up`（任务书 02）。

## 一、前置

- 已安装 Docker（含 Docker Compose v2）。
- 本仓库根目录执行过依赖安装（仅本地开发需要；容器构建自带）。

## 二、准备环境变量（可选）

```bash
cp .env.example .env
# 按需修改 .env 中的密码 / 密钥（默认值可直接跑通）
```

`docker-compose.yml` 会从 `.env` 读取变量（均有默认值，不复制也能起）。

## 三、一条命令起全栈

```bash
# 构建并后台启动全部服务（首次会自动构建 web / api 镜像）
docker compose up -d --build

# 查看启动进度与各服务健康状态
docker compose ps

# 跟踪日志（api / web 排错常用）
docker compose logs -f api
docker compose logs -f web
```

## 四、各服务地址（宿主机访问）

| 服务 | 地址 | 说明 |
|---|---|---|
| 门户 web | http://localhost:3000 | Next.js 门户 |
| 后端 api | http://localhost:8000 | FastAPI；文档 http://localhost:8000/docs |
| 后台 Directus | http://localhost:8055 | headless CMS 管理后台 |
| 搜索 Meilisearch | http://localhost:7700 | 搜索服务（后期接入） |
| 数据库 MySQL | 不暴露到宿主机 | directus / api 经内部网络 `wk` 访问 |

> MySQL 默认**不发布端口**：宿主机常已装 MySQL 占用 `127.0.0.1:3306`，发布会相互遮蔽。确需从宿主机直连容器 MySQL 时，把 `docker-compose.yml` 中 mysql 的 `ports` 改为不冲突端口（如 `"3307:3306"`）再 `up`。

## 五、首次初始化 Directus 管理员

1. 打开 http://localhost:8055 ，用 `.env` 中的 `DIRECTUS_ADMIN_EMAIL` / `DIRECTUS_ADMIN_PASSWORD`（默认 `admin@worldknowledge.org` / `password`）登录。
2. 首次启动后若需重置管理员，停止容器并删除 `directus_uploads` 卷后重新 `up`。

## 六、localhost 还是服务名？（重要）

- **容器内部**（服务端组件、API↔API 调用）：用 compose **服务名**，`http://api:8000`、`http://directus:8055`、`http://mysql:3306`、`http://meilisearch:7700`。
- **宿主机浏览器**：用 **`localhost`**，`http://localhost:8000`、`http://localhost:8055`。

门户容器内通过 `NEXT_PUBLIC_API_BASE_URL=http://api:8000` 注入，正是为了容器内正确寻址；请勿在容器里用 `localhost` 指 API（那会指向容器自己）。

## 六点五、重启策略与启动顺序（重要）

- `mysql` / `directus` 已配置 `restart: unless-stopped`：当 MySQL 尚未就绪时，Directus 首次连库可能 `ECONNREFUSED` 退出，容器会自动重启重试，**无需手工 `docker compose start directus`**。
- 服务间用 `depends_on: condition: service_healthy` 串起启动顺序：`directus`/`api` 等 MySQL 就绪，`web` 等 `api` 就绪。
- 冷启动（首次建库 + 初始化）可能耗时 1–2 分钟，`docker compose ps` 里各服务变为 `(healthy)` 即就绪。

## 七、停止 / 清理

```bash
docker compose down            # 停止并移除容器（数据卷保留）
docker compose down -v         # 连同数据卷一起删除（清空 MySQL / Directus 数据）
```

## 八、已知限制 / 待确认

- 门户首页（`/`）当前为**构建期静态预渲染**：由于构建镜像时 API 尚未就绪，首页会在构建期快照化。若需门户在运行时实时拉取「四阶段」等数据，**需下游分支（04）将门户页面标记为动态渲染**（`export const dynamic = 'force-dynamic'` 或对 API 的 `fetch` 设置 `cache: 'no-store'`）。深层路由 `/stage/[stage]/[discipline]` 已是动态渲染（`ƒ`），运行时拉取正常。
- `directus` 使用 `:latest` 标签，生产建议锁版本。
